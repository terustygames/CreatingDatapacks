# Как увидеть настоящий текст ошибки

Сообщение «Не удалось проверить набор данных» — это заглушка. Настоящая причина
с именем файла всегда пишется в лог. Достать её можно тремя способами.

---

## Способ 1 — кнопка в самом окне ошибки (быстрее всего)

Когда выскакивает «Не удалось проверить набор данных», там есть кнопки.
Нажмите **«Подробнее»** / **«Details»** — развернётся текст с путём к файлу.

Если кнопки нет, а есть только «Продолжить»/«Отмена» — переходите к способу 2.

---

## Способ 2 — вывод игры в лаунчере (самый надёжный)

1. Откройте лаунчер Minecraft.
2. Слева **«Настройки Java»** (или шестерёнка → Настройки).
3. Включите галочку **«Открывать вывод игры»**
   (в англ. — *Open output log when game starts*).
4. Запустите игру и повторите создание мира.
5. Откроется чёрное окно с логом. Найдите там строки со словом **ERROR**.

Ищите глазами что-то из этого:

```
Failed to load ...
Couldn't parse data file ...
Error while loading ...
Unbound values in registry ...
Missing ...
```

**Пришлите мне 10–20 строк вокруг первого ERROR.** Этого хватит, чтобы починить точно.

---

## Способ 3 — файл лога на диске

Лог всегда пишется на диск, даже без галочки.

Нажмите `Win + R`, вставьте и Enter:

```
%appdata%\.minecraft\logs
```

Откройте **`latest.log`** блокнотом. Если игра уже закрыта — там лог последнего
запуска. Ищите `ERROR` (Ctrl+F).

Полезно: рядом лежат `debug.log` (подробнее) и архивы `.log.gz` за прошлые дни.

# Тесты: сузить причину до одного файла

В этой папке 4 мини-пака. Грузите их **по одному**, каждый — в отдельный
новый мир. Так станет ясно, что именно ломается.

Каждый тест — это папка с `pack.mcmeta` внутри, то есть полноценный датапак.
Кладите в `.minecraft/saves/<мир>/datapacks/` или в `.minecraft/datapacks/`.

| Тест | Что внутри | Если ОШИБКА | Если РАБОТАЕТ |
|---|---|---|---|
| **ТЕСТ-1A-формат-94.1** | только `pack.mcmeta` с `max_format: 94.1` | дело в дробном формате → берём 1B | формат ок |
| **ТЕСТ-1B-формат-94-1** | только `pack.mcmeta` с `[94, 1]` | дело не в формате | **надо писать массивом** |
| **ТЕСТ-2-пресет-ванильный** | пресет `normal`, настройки ванильные | ломается сам пресет | пресет ок |
| **ТЕСТ-3-наша-генерация** | наши `empty_overworld` / `empty_nether` | ломается генерация | генерация ок |

## Главное, что проверяет пара 1A / 1B

Тут я, возможно, ошибся раньше, когда откатил формат обратно по вашей просьбе.

В JSON `94.1` — это **дробное число** (в памяти оно вообще `94.0999999...`).
А Minecraft ждёт либо целое, либо массив `[94, 1]`, где `94` — мажорная версия,
`1` — минорная. Это не одно и то же.

Возможны два исхода:

- **1A работает** — значит игра дробное принимает (молча усекает до 94),
  и `94.1` действительно рабочий вариант. Тогда я был неправ, что вообще это трогал.
- **1A даёт ошибку, 1B работает** — значит писать надо массивом,
  и мой первоначальный правкой был по делу, просто я её не объяснил
  и зря заодно поднял `min_format`.

Проверка займёт минуту и закроет вопрос окончательно — вместо споров.

## Что мне прислать

Достаточно чего-то одного:

1. Строки с `ERROR` из лога (способ 2 или 3) — **это лучше всего**.
2. Или просто результат тестов: например «1A — ошибка, 1B — работает,
   2 — работает, 3 — ошибка».
3. Или фото/скриншот окна с ошибкой, если развернули «Подробнее».

По любому из этих трёх я найду причину точно, без гаданий.
