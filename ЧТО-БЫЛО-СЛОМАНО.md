# Почему датапак не работал и что я починил

## 1. Ошибка VS Code на `minecraft:nether/vegetation`

В прошлый раз в пак положили файл
`One block water 1.21.11/data/minecraft/worldgen/noise_settings/nether.json`,
в котором было написано:

```json
"vegetation": {
  "type": "minecraft:shifted_noise",
  "noise": "minecraft:nether/vegetation",
  ...
}
```

Такого шума в игре **нет**. В `data/minecraft/worldgen/noise/` у ванилы есть
`vegetation.json`, `temperature.json`, `offset.json` и т.д. — без папки `nether/`.
Префикс `nether/` существует только у density-функций
(`minecraft:nether/base_3d_noise`), а не у noise-параметров.
Правильный id — просто `minecraft:vegetation` (и `minecraft:temperature`).

Поэтому VS Code (и сама игра при загрузке мира) ругались.

**Важно:** этот файл вообще не был нужен — см. пункт 2.

## 2. Главная поломка: пак переписывал ванильную генерацию вместо своей

Изначально (коммит `9372a67`) пак был устроен правильно:

- своя генерация лежала в `data/oneblockwater/worldgen/noise_settings/empty_overworld.json`
  и `empty_nether.json`;
- `world_preset/normal.json` ссылался на них: `"settings": "oneblockwater:empty_overworld"`.

В коммите `f781e8a` это всё **удалили** и вместо этого положили файлы в
`data/minecraft/worldgen/noise_settings/`, то есть стали перезаписывать
ванильные `minecraft:overworld` и `minecraft:nether`, а `normal.json` вернули
на `"settings": "minecraft:overworld"`.

Заодно были удалены:

- все функции (`first_join`, `tick`, `load`, `nether_join`, `place_portal`);
- теги `minecraft:tags/function/load.json` и `tick.json` — без них функции
  вообще никогда не запускаются;
- `structure/ender_portal.nbt`;
- `processor_list/empty_all.json`;
- `pack.png`.

То есть от датапака осталась только генерация — ни спавна, ни блока воды,
ни портала. Он «не работал» именно поэтому.

**Что сделал:** вернул всю рабочую структуру из `9372a67` и удалил
`data/minecraft/worldgen/noise_settings/` целиком. Preset снова указывает на
`oneblockwater:empty_overworld` / `oneblockwater:empty_nether`.

Кстати, в старых файлах `preliminary_surface_level` уже стоит правильно —
в 1.21.9 поле `initial_density_without_jaggedness` заменили на него,
так что для 1.21.11 они корректны.

## 3. `pack.mcmeta`: формат версии был числом с точкой

Было:

```json
"min_format": 88,
"max_format": 94.1
```

`94.1` — не число, а «мажор 94, минор 1». Игра такое либо обрежет до 94,
либо отвергнет, а линтер в VS Code точно подчеркнёт. Правильно писать массивом:

```json
"min_format": [94, 0],
"max_format": [94, 1]
```

Плюс `min_format: 88` (1.21.9) означал бы поддержку версии, в которой часть
формата уже другая — сузил до 94.

## 4. Портал ставился каждый раз заново

`place_portal.mcfunction` проверялся через
`unless data storage oneblockwater:state {portal_placed:1b}`,
но флаг `portal_placed` **нигде не выставлялся**. Добавил в конец функции:

```
data modify storage oneblockwater:state portal_placed set value 1b
```

# Отдельно про папку `empty-world-with-biomes-1-20`

Это чужой пак (Moimrvince, 2022, CC BY-NC-ND), сделанный под **1.19/1.20**:

- в `pack.mcmeta` стоит `"pack_format": 15` — это 1.20/1.20.1;
- папки называются по-старому: `advancements`, `functions`, `structures`
  (в 1.21 они в единственном числе: `advancement`, `function`, `structure`);
- в его `noise_settings` используется `initial_density_without_jaggedness`,
  которого в 1.21.9+ больше нет.

На 1.21.11 он просто не загрузится (или загрузится с ошибками) — это нормально,
и это **не** причина проблем с «One Block Water». Я его не трогал, потому что
лицензия запрещает производные работы (NoDerivatives). Если он нужен на 1.21.11 —
надо либо искать обновлённую версию у автора, либо делать свой аналог с нуля.

Файл `skyvoid_worldgen_single_lava_v0.1.2.zip` — тоже сторонний, `pack_format: 10`
(1.19). Его в игру на 1.21.11 тоже класть бесполезно.

# Как проверить

1. Скопируй папку `One block water 1.21.11` в `.minecraft/saves/<мир>/datapacks/`,
   либо в `.minecraft/datapacks/` перед созданием мира.
2. При создании мира выбери тип мира **Normal** — пак подменяет пресет `normal`,
   поэтому генерация будет пустой.
3. Включи логи в лаунчере: любые ошибки worldgen видно там сразу.
